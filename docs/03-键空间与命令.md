# 第 3 章：键空间与命令 —— dict 上的一层薄皮

实现见 [`tinyredis/storage.py`](../tinyredis/storage.py) 和
[`tinyredis/commands.py`](../tinyredis/commands.py)。

## 三种结构，两个字典

真实 Redis 有 SDS 字符串、ziplist/listpack、skiplist 等七八种底层编码。
tiny-redis 砍到三种：

```python
class StringValue: value: bytes          # SET/GET/INCR/APPEND...
class ListValue:   value: list[bytes]    # LPUSH/RPUSH/LRANGE/LPOP...
class HashValue:   value: dict[bytes, bytes]  # HSET/HGET/HGETALL...
```

键空间就是两个字典：

```python
self._data = {}       # key -> Value
self._expires = {}    # key -> 过期时刻（Unix 秒，浮点）
```

够快（dict/list 都是 C 实现），够简单（每个方法一眼看完），
类型系统保留（`WRONGTYPE` 错误与真实 Redis 一致）。

## 命令表的形状

每条命令注册一个处理函数和 arity（参数个数约束，语义与 Redis 相同：
正数是精确个数、负数是下限，**都包含命令名本身**）：

```python
COMMANDS = {
    "SET":  (cmd_set, -3),    # 至少 2 个参数：key value [选项...]
    "GET":  (cmd_get, 2),     # 恰好 1 个参数
    "DEL":  (cmd_del, -2),    # 至少 1 个参数
    ...
}
```

派发只做三件事：查表、检查 arity、调用。统一入口
`commands.execute(store, args)` 让单元测试可以直接喂命令而不用起服务器。

## 错误信息逐字对齐 Redis

兼容性的一半在协议，另一半在错误语义。tiny-redis 对齐了常见的：

| 场景 | 错误 |
| :-- | :-- |
| 参数不对 | `ERR wrong number of arguments for 'get' command` |
| 类型不对 | `WRONGTYPE Operation against a key holding the wrong kind of value` |
| INCR 非整数 | `ERR value is not an integer or out of range` |
| RENAME 不存在的键 | `ERR no such key` |
| SET 语法错 | `ERR syntax error` |

客户端库（如 redis-py）把这些错误转成异常抛给业务代码——错误串对不上，
上层的行为就对不上。

## 几个值得展开的细节

**SET 的选项解析**。`SET k v EX 10 NX GET` 有七种可组合的选项，
一个状态机循环搞定，非法组合（`NX` + `XX`、负过期时间）明确报错。

**INCR 的溢出检查**。Redis 对 64 位有符号整数溢出报错，tiny-redis 一样：

```python
total = current + delta
if not (-(2 ** 63) <= total < 2 ** 63):
    raise NotIntegerError(...)
```

**空容器自动删除**。列表/哈希弹出最后一个元素后自动把键删掉——
Redis 的语义，省内存，也让 `TYPE` 返回 `none` 而不是空 `list`。

**KEYS 的模式匹配**。Redis glob 与 Python `fnmatch` 几乎一致，只差
取反写法（Redis `[^x]`，fnmatch `[!x]`），一行翻译解决。

## MGET 的宽容与 GET 的严格

对错误类型的键：`GET` 报 `WRONGTYPE`，`MGET` 却返回 `nil` 继续——
这也是真实 Redis 的行为（批量命令对单个坏键宽容，单个命令严格）。
细节对齐与否，直接决定客户端库能不能正常工作。

## 小结

- 两个 dict + 三个值类型，覆盖三种核心数据结构；
- 命令 = 处理函数 + arity，统一入口方便测试；
- 错误串逐字对齐，是"能用官方客户端连上"的另一半。
