# 第 5 章：客户端、兼容性与测试

## 自带客户端：与服务器共用一半代码

`tinyredis.client.Redis` 是一个同步阻塞客户端，**发送方向**直接复用
`protocol.encode_command`，**接收方向**独立实现了一个小递归下降解析器：

```python
def _read_reply(self):
    while True:
        reply, consumed = _parse_reply(self._buf)   # 能解析就返回
        if consumed:
            del self._buf[:consumed]
            return reply
        chunk = self._connect().recv(65536)          # 不够就再读一段
        self._buf += chunk
```

和服务器方向同样的"缓冲区 + 增量解析"套路。五种 RESP 类型映射到
Python：`+` → str，`:` → int，`$` → bytes/None，`*` → list；
`-` 抛 `ResponseError`。

```python
from tinyredis.client import Redis
with Redis(port=6379) as r:
    r.set("greeting", "你好")
    print(r.get("greeting"))          # b'\xe4\xbd\xa0\xe5\xa5\xbd'
```

客户端不做连接池、不并发——单连接单实例，与真实 Redis 客户端的
最小用法一致。

## "兼容"的实战清单

tiny-redis 能被官方 redis-py 直接驱动（`scripts/compat_check.py`，
23 项检查全过），靠的是下面这些实战点：

1. **HELLO 握手**。redis-py ≥ 5 建立连接时会发 `HELLO`，没有这条命令
   连 PING 都发不出去。RESP2 模式下应答是扁平数组形式的 map。
   注意：tiny-redis 只支持 RESP2，redis-py 8.x 默认尝试 RESP3，
   要显式 `Redis(protocol=2)`；服务器对 `HELLO 3` 回 `NOPROTO` 错误；
2. **COMMAND DOCS**。redis-cli 连上后会拉命令文档，回一个空数组让它安静；
3. **错误串逐字对齐**。`WRONGTYPE`、`ERR no such key`……客户端库
   按字符串匹配行为，差一个词上层逻辑就变了；
4. **HSET 多字段**。`HSET key f1 v1 f2 v2` 是一条命令，arity 是 -4；
5. **MGET 宽容**。批量命令对单个坏键返回 `nil` 而不是整体报错。

反过来不做的：`CLIENT SETINFO` 这类增强命令让它收到
`unknown command` 错误——redis-py 对此类失败自带容忍。

## 测试金字塔

133 个用例，四层：

| 层 | 内容 | 数量 |
| :-- | :-- | --: |
| 协议单元 | 数组/内联解析、逐字节喂入、非法报文、编码往返 | ~20 |
| 存储单元 | 三种结构、TTL 语义、rename 带 TTL、主动过期 | ~45 |
| 命令单元 | 每条命令的正例/错误例，直接喂 `execute()` | ~40 |
| 端到端 | 真实 socket：并发 INCR 原子性、协议错误断连、快照恢复 | ~25 |

最有价值的三个端到端用例：

- **`test_parallel_incr_is_atomic`**：4 客户端并发 INCR × 200，
  终值必须精确 800——单线程事件循环的原子性由测试背书；
- **`test_save_then_reload_into_new_server`**：SAVE → 起新服务器 →
  数据原样回来；
- **`test_flipped_byte_detected_by_crc`**：快照文件翻转一个字节，
  加载必须失败——持久化的可靠性由测试背书。

## 基准

`scripts/benchmark.py`，顺序模式（每条命令等应答，无 pipeline），
单连接，Windows / Python 3.14：

```
SET : 13010 ops/s
GET : 15330 ops/s
INCR: 16887 ops/s
```

顺序模式衡量的是单连接往返延迟（HTTP 语义级别的对比才有意义）；
真实 Redis 同模式下也大约在这个量级的 3-5 倍。tiny-redis 的瓶颈
不在数据结构而在 Python 本身——这正是教学项目该有的诚实结论。

## 小结

- 客户端 = 发送复用 + 接收独立递归解析；
- 兼容性是一张清单：HELLO、错误串、多字段 HSET、批量命令的宽容语义；
- 测试金字塔 + 三个"靠山用例"，是这个项目敢叫"实现"而不是"玩具"的底气。
