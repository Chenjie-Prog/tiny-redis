# 第 2 章：事件循环 —— 为什么单线程反而是优点

实现见 [`tinyredis/server.py`](../tinyredis/server.py)。

## tiny-redis 的骨架

整个服务器就是一个循环：

```python
def _loop(self):
    while not self._shutdown:
        events = self._selector.select(timeout=0.1)
        for key, mask in events:
            if key.data is None:        # 监听 socket -> 新连接
                self._accept(key.fileobj)
            else:                        # 客户端 socket -> 读/写事件
                self._handle_event(key, mask)
        self._periodic()                 # 主动过期 + 定时快照
```

所有 socket 都是**非阻塞**的，统一注册在 `selectors.DefaultSelector` 上
（Linux 上是 epoll，macOS 是 kqueue，Windows 是 select——标准库帮你选好了）。
事件到达才处理，没事件就 `select` 睡 0.1 秒，顺便给"主动过期"留出机会。

## 为什么单线程

真实 Redis 把命令执行放在单线程里（网络 IO 在 6.0 后拆给了 I/O 线程），
理由是：**命令一旦串行执行，每条命令天然原子**。

tiny-redis 走得更极端：网络 IO 也在同一个循环里。好处：

1. **零锁**。数据结构不需要任何互斥保护，因为同一时刻只有一个线程在碰它；
2. **原子性免费**。`INCR` 就是真 INCR，两个客户端并发 `INCR` 一千次，
   结果精确等于一千（`test_parallel_incr_is_atomic` 验证了这一点）；
3. **代码就是 Redis 的心智模型**。想理解 Redis 的并发语义，读这个循环就够了。

代价：

1. 一条慢命令会卡住所有连接（所以命令层绝不写慢操作）；
2. **不能有阻塞命令**。`BLPOP` 这类"挂着等数据"的命令会把整个服务器
   卡死，tiny-redis 干脆不实现（见 README 路线图：要支持就得引入
   "挂起客户端队列 + 数据就绪时唤醒"的机制）。

## 非阻塞读写的完整闭环

读方向：

```python
def _do_read(self, conn):
    data = conn.sock.recv(_RECV_SIZE)   # 非阻塞，没数据抛 BlockingIOError
    if not data:                        # 对端关闭
        self._close_conn(conn)
        return
    conn.parser.feed(data)
    while True:
        args = conn.parser.next_command()   # 完整命令可能不止一条
        if args is None:
            break
        self._execute(conn, args)
```

写方向有个容易忽略的坑：`send()` 不保证一次发完。正确做法是维护
**发送缓冲区**：

```python
def _flush(self, conn):
    sent = conn.sock.send(bytes(conn.out))
    del conn.out[:sent]                 # 没发完的留在缓冲区
    want = selectors.EVENT_READ | (selectors.EVENT_WRITE if conn.out else 0)
    self._selector.modify(conn.sock, want, conn)   # 发不完就订阅"可写"
```

缓冲区非空时订阅 `EVENT_WRITE`，内核缓冲腾出空间了再继续发；
发完了改回只订阅读。这就是"背压"的最小实现。

## 例行任务

`_periodic()` 每个 tick 做两件事：

1. **主动过期采样**（第 4 章详述）——每 0.1 秒从过期表里抽样删过期键；
2. **定时快照**——配置了 `--snapshot-interval` 且数据变脏时写快照文件。

这也是事件循环模型的另一个好处：例行任务不用自己开线程，找个空档
插入循环就行，天然和命令执行串行，没有并发问题。

## 小结

- `selectors` + 非阻塞 socket + 发送缓冲区 = 单线程跑所有连接；
- 单线程换来零锁和天然原子性，代价是不允许阻塞和慢命令；
- 例行任务（过期、快照）直接嵌在循环里，最省心。
